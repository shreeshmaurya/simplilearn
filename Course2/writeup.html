1. Project Overview

HR Portal is a fully client-side enterprise Human Resources management application built using React 19, React Router, and Vite. The application enables HR professionals to manage employee records, review and act on leave requests, and oversee workforce data through an intuitive dashboard. Employees can register, view and update their personal profiles, and submit leave applications.

The project demonstrates modern React development practices including component-based architecture, context-based state management, role-based access control, protected routing, form validation with real-time feedback, and JSON-based data persistence using localStorage.

4. Features Implemented

4.1 User Authentication (Login & Signup)

  • Login form with email and password fields, real-time validation, and error feedback.
  • Authentication against JSON-stored user records in localStorage.
  • Role-based redirect: HR users go to /hr/dashboard, employees go to /employee/dashboard.
  • Session persistence — logged-in users remain authenticated across page refreshes.
  • Logout clears session data and redirects to the login page.
  • Demo credentials displayed on the login page for easy testing.

4.2 Employee Registration (Signup)

  • Multi-field registration form: first name, last name, email, phone, department, position, password.
  • Department selection from a predefined dropdown list (Engineering, Marketing, Finance, etc.).
  • Password strength indicator with real-time visual feedback (weak/medium/strong).
  • Password confirmation with mismatch detection.
  • Duplicate email prevention with appropriate error messages.
  • New users are automatically assigned the "employee" role and redirected to their dashboard.

4.3 Role-Based Access Control (RBAC)

  • Two distinct roles: HR and Employee, each with dedicated routes and UI.
  • ProtectedRoute component guards all authenticated routes.
  • Cross-role access is blocked: employees cannot access /hr/* routes and vice versa.
  • Unauthenticated users are redirected to the login page from any protected route.
  • Role-specific navigation menus and role badges displayed in the header.

4.4 HR Dashboard

  • Four statistics cards: Total Employees, Active Employees, Pending Leave Requests, Departments.
  • Recent Employees table with name, department, and status columns.
  • Recent Leave Requests table with employee name, leave type, and status badges.
  • Quick navigation links to the Employee Management and Leave Management pages.

4.5 Employee Profile Management (HR)

  • Full employee list with tabular display showing name, email, department, position, join date, and status.
  • Search: Real-time filtering by name or email address.
  • Filter: Department-based dropdown filter.
  • Add Employee: Modal form to create new employee records with all required fields.
  • Edit Employee: Modal form pre-filled with existing data for updating records.
  • Activate/Deactivate: Toggle employee status between active and inactive.
  • Delete: Remove employee with a confirmation dialog to prevent accidental deletion.

4.6 Employee Data Storage (JSON)

  • All employee profiles are stored as JSON objects in the browser's localStorage.
  • Seed data includes 4 pre-configured users (1 HR manager + 3 employees) for immediate testing.
  • A dedicated storage utility module (utils/storage.js) provides CRUD functions for users and leave requests.
  • Data is initialized on first load and persists across browser sessions.

4.7 Leave Request Management

  • Employee side: Apply for leave with type selection (Annual, Sick, Personal, Maternity/Paternity, Unpaid), date range, and reason.
  • Leave history table with status badges (pending, approved, rejected) and filter by status.
  • HR side: View all leave requests across the organization with employee name and details.
  • Approve or reject pending requests with one click; reviewer name and date are recorded.
  • Filter by status and leave type for efficient review.
  • Pending request count displayed on the page header.

4.8 Employee Dashboard & Profile

  • Personalized welcome message and leave statistics (total, approved, pending, rejected).
  • Profile summary card with avatar initials, name, email, department, position, and join date.
  • Editable profile: employees can update their first name, last name, and phone number.
  • Department and position fields are read-only (HR-managed).
  • Success/error feedback after profile updates.

4.9 Responsive UI & Navigation

  • Sidebar navigation: Fixed dark sidebar with role-specific menu items and SVG icons.
  • Header bar: Displays greeting, user role badge, and responsive menu toggle.
  • Mobile responsive: Sidebar collapses to an overlay on screens below 768px.
  • Tablet responsive: Stats grid adjusts from 4 columns to 2 columns on medium screens.
  • Professional CSS theme using CSS custom properties for consistent styling across all components.

4.10 Enterprise CSS Styling

  • Complete design system with CSS custom properties for colors, spacing, shadows, and border radii.
  • Blue enterprise color scheme with primary, success, warning, danger, and info variants.
  • Card-based layouts with subtle shadows, rounded corners, and hover effects.
  • Status badges with color-coded backgrounds for active/inactive, approved/rejected/pending states.
  • Gradient login page background with centered authentication card.
  • Consistent form styling with focus states, disabled states, and field-level error messages.
  • Modal overlays with backdrop blur for add/edit forms and confirmation dialogs.

5. How to Run the Application

Step 1: Ensure Node.js (v18 or higher) is installed on your system.
Step 2: Open a terminal and navigate to the hr-portal directory.
Step 3: Install dependencies:
npm install
Step 4: Start the development server:
npm run dev
Step 5: Open the displayed URL (e.g., http://localhost:5173) in your browser.
Step 6: Log in with the demo credentials:
   • HR Manager: admin@hrportal.com / Admin@123
   • Employee: john.doe@hrportal.com / Employee@123
Step 7: As HR, explore the Dashboard, manage Employees, and review Leave Requests.
Step 8: Log out and log in as an Employee to view the Employee Dashboard, update your Profile, and apply for Leave.
Step 9: To run the Playwright E2E test suite:
npm run build && npm run test:e2e
Note: The application is entirely client-side. No backend server is required. All data (users, leave requests, sessions) is stored in the browser's localStorage as JSON. The seed data is automatically loaded on first visit.

6. End-to-End Testing

The application includes a comprehensive Playwright test suite with 61 end-to-end tests across 7 test files:

  • auth.spec.js (9 tests) — Login form display, validation errors, successful login for both roles, logout.
  • signup.spec.js (7 tests) — Registration form, field validation, password strength, duplicate prevention, successful registration.
  • rbac.spec.js (8 tests) — Route protection, cross-role redirect blocking, role-specific navigation and badges.
  • dashboard.spec.js (11 tests) — HR and Employee dashboard statistics, tables, navigation links.
  • employee-management.spec.js (8 tests) — Employee list, search, filter, add, edit, delete with confirmation.
  • leave-management.spec.js (12 tests) — Employee leave apply/view/filter, HR approve/reject/filter.
  • profile.spec.js (6 tests) — Profile display, edit mode, save changes, cancel, disabled fields.

7. Key React Concepts Demonstrated

  • Component-Based Architecture: 14 reusable React components organized by feature (auth, layout, dashboard, employees, leave).
  • React Context API: Centralized authentication state with AuthContext providing user data, login, signup, and logout functions to all components.
  • React Router v7: Nested route configuration with layout routes, index redirects, and programmatic navigation.
  • Protected Routes: Custom ProtectedRoute component wrapping route groups with authentication and role checks.
  • Controlled Forms: All forms use React controlled components with useState for form data, validation errors, and submission state.
  • Hooks: Extensive use of useState, useEffect, useCallback, useMemo, and useContext for state management and performance optimization.
  • Conditional Rendering: Role-based UI rendering, edit/view mode toggling, modal visibility, and empty state handling.
  • CSS Custom Properties: Full design system with CSS variables for theming, enabling consistent styling across all components.
  • Responsive Design: CSS media queries at 1024px, 768px, and 480px breakpoints for desktop, tablet, and mobile layouts.
